# iLy. アニメーション品質レビュー

iLy.（育児サイト）で演出・アニメーションを実装した**あと**に、品質と世界観の一貫性を確認するためのSkill。
実装の善し悪しを「iLy.らしさ」の観点でレビューし、問題があれば具体的に指摘する。

## 前提となる世界観（絶対に守る）

- **白背景・上品・柔らかさ**：iLy.は育児サイト。清潔感のある白基調と、角の丸い・ゆったりした柔らかい印象を崩さない。
- **派手なAIっぽい演出はNG**：ネオングロー、強い発光、過剰なパララックス、高速で弾むような大きい動き、ギラついたグラデーション、無限に動き続ける装飾などは避ける。
- 動きは「そっと現れる」「ふわっと馴染む」程度の控えめさに留める。イージングは ease / ease-out 系の穏やかなものを基本とし、派手なバウンスや overshoot は使わない。

## レビュー手順

以下を順番に確認し、それぞれ ✅ / ⚠️ / ❌ で結果を報告する。

### 1. 世界観の一貫性
- 追加された演出が白背景・上品・柔らかさを保っているか。
- 派手・AIっぽい・育児サイトに不釣り合いな演出になっていないか。
- 動きの量・速度・振幅が控えめか（大きく弾む/高速で動く/光るものは要注意）。

### 2. SP（スマホ）表示
- **必ず** モバイル幅での見え方を確認する（`npm run dev` で起動し、375px前後の幅で確認、または該当CSSのメディアクエリを読む）。
- SPで演出がはみ出す・重なる・崩れる・横スクロールを誘発していないか。
- タッチ操作を阻害していないか（hover前提の演出がSPで問題にならないか）。

### 3. prefers-reduced-motion 対応
- アニメーションが `@media (prefers-reduced-motion: reduce)` に対応しているか確認する。
- 未対応なら、モーションを無効化 or 大幅に軽減するフォールバックを提案する。
- JSでモーションを制御している場合は `window.matchMedia('(prefers-reduced-motion: reduce)')` を尊重しているか確認する。

### 4. パフォーマンス（重さ）
- scroll / resize / mousemove 等のイベントで重い処理をしていないか。デバウンス/スロットル、`requestAnimationFrame`、`passive` リスナーの利用を確認する。
- アニメーションが `transform` / `opacity` 中心で GPU に優しいか（`top`/`left`/`width`/`height` の連続アニメでレイアウトを毎フレーム再計算していないか）。
- IntersectionObserver で済むものを scroll イベントで無理に処理していないか。
- 無限ループアニメーションが常時走り続けてバッテリー/CPUを浪費していないか。

### 5. 既存デザインへの副作用
- 追加した CSS / グローバルスタイルが他コンポーネントに影響していないか（グローバルセレクタ、`*`、`body`、共通クラスの上書きに注意）。
- z-index の衝突、レイアウトのずれ、既存アニメーションとの競合がないか。
- 変更のあったファイルの周辺だけでなく、共有スタイルを触った場合は影響範囲を確認する。

### 6. ビルド確認
- `npm run build`（= `tsc && vite build`）を実行し、TypeScript の型エラーとビルドエラーがないことを確認する。
- 失敗した場合はエラー内容をそのまま報告する。

## 禁止事項（このSkillでは絶対にやらない）

- **DB / Supabase migration には触らない。** スキーマ・マイグレーション・データ操作は一切変更しない。
- **commit / push はしない。** レビューと必要な修正提案・修正の適用までに留め、git のコミット・プッシュはユーザーに委ねる。

## 報告フォーマット

各観点（1〜6）を ✅ 問題なし / ⚠️ 要確認 / ❌ 要修正 で列挙し、⚠️・❌ には該当ファイル・行と具体的な改善案を添える。最後に総評を一言添える。
